# Architecture Decisions

| ID    | Decision                                                                                                                                                                                             | Status     | Consequence                                                                                                                                                                                                                  |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | Position Field Runtime Core as an Enterprise Case Runtime, not a generic agent or workflow builder.                                                                                                  | Accepted   | Product evaluation is case-first, not chat-first.                                                                                                                                                                            |
| D-002 | Use a TypeScript pnpm monorepo and one modular deployable.                                                                                                                                           | Accepted   | Package boundaries are explicit without premature distributed systems.                                                                                                                                                       |
| D-003 | Use PostgreSQL as the canonical persistence target.                                                                                                                                                  | Accepted   | SQLite may not replace it silently; local convenience requires a future conformance decision.                                                                                                                                |
| D-004 | Keep authority, scope, identity, state transitions, idempotency, and closure outside models.                                                                                                         | Accepted   | Agent and model outputs are proposals only.                                                                                                                                                                                  |
| D-005 | Ship v0 as a synthetic, credential-free, no-external-write evaluation appliance.                                                                                                                     | Accepted   | Installation may be easy; production authority requires a separate graduation process.                                                                                                                                       |
| D-006 | Put models, agent harnesses, memory systems, work surfaces, and connectors behind bounded adapters outside the trusted core.                                                                         | Accepted   | Providers are replaceable and cannot own canonical case state.                                                                                                                                                               |
| D-007 | Make Escalation and Commitment Control the only initial workflow pack.                                                                                                                               | Accepted   | Product proof stays workflow-specific.                                                                                                                                                                                       |
| D-008 | Defer public licensing until the distribution and commercial open-core boundary is approved.                                                                                                         | Superseded | D-026 approves the public evaluation-preview boundary.                                                                                                                                                                       |
| D-009 | Treat workflow YAML, authority YAML, canonical JSON Schema, and cross-record invariants as the v0 contract; keep generated PostgreSQL SQL as reference until parity is reconciled.                   | Accepted   | Contract drift is explicit and cannot silently redefine runtime behavior.                                                                                                                                                    |
| D-010 | Import ECC v0.1.0 as immutable shadow/evaluation-only and deny activation until graph, authority, fixture, and persistence parity blockers are repaired in a new version.                            | Accepted   | The baseline remains useful without overstating executable safety.                                                                                                                                                           |
| D-011 | Keep normalized inbound `WorkEvent` records distinct from authoritative `CaseJournalEntry` history.                                                                                                  | Accepted   | Source evidence retains its provider-neutral shape while aggregate replay gains sequence, attribution, causation, and hash-chain semantics.                                                                                  |
| D-012 | In PR2, attach a WorkEvent only to an explicitly identified case; defer automatic ECC candidate selection until its merge basis and ambiguity policy are executable.                                 | Accepted   | The runtime cannot guess a case from insertion order or incomplete business discriminators.                                                                                                                                  |
| D-013 | Deny every transition to `resolved` until the complete closure-proof engine can validate action/no-action, independent verification, commitments, accepted outcome, and audit.                       | Accepted   | PR2 demonstrates the lifecycle without making an unproved resolution authoritative.                                                                                                                                          |
| D-014 | Journal an attributable transition rejection and advance aggregate version while leaving business state unchanged; malformed commands, conflicts, and duplicates do not append.                      | Accepted   | Investigations retain the attempted operation without confusing it with an accepted state change.                                                                                                                            |
| D-015 | Treat PR2 as an in-memory reference engine; require PR4 to atomically persist journal, projection, idempotency, and source-event identity.                                                           | Accepted   | Deep freezing and hash validation do not imply process-safe concurrency or durable immutability.                                                                                                                             |
| D-016 | Return an already-processed conflict when an exact source event is replayed under a fresh idempotency key; only the original same-key command is an exact duplicate.                                 | Accepted   | PR2 avoids an unjournaled alias ledger while guaranteeing that the source event has no duplicate case effect.                                                                                                                |
| D-017 | Fail closed on every claimed `executed` action until Delivery PR6 defines and recomputes a versioned authorization-envelope hash.                                                                    | Accepted   | Caller-declared hashes, approvals, and receipts cannot be mistaken for execution proof.                                                                                                                                      |
| D-018 | Normalize inbound WorkEvent occurrence time to exact millisecond UTC before identity, hashing, journaling, or persistence, and require separate source-timezone metadata.                            | Accepted   | Equivalent instant spellings behave identically while the source's business-time context remains available.                                                                                                                  |
| D-019 | Normalize every caller-supplied case-creation seed instant to exact millisecond UTC before identity, hashing, journaling, or persistence, and require field-specific source-timezone metadata.       | Accepted   | Workflow effective windows and case deadlines have stable identities while supplied timezone labels remain available; adapters validate label/instant coherence.                                                             |
| D-020 | Persist PR4 as a lossless canonical JSONB projection plus immutable journal and relational identity/topology indexes; keep the drifted normalized reference SQL non-authoritative.                   | Accepted   | PostgreSQL durability cannot silently change Case vocabulary, omit timezone context, or bless unresolved upstream parity gaps.                                                                                               |
| D-021 | Deploy one API process with the transactional worker in-process and serialize PR4 writes through one PostgreSQL singleton lock.                                                                      | Accepted   | The local appliance preserves whole-engine/global-ID integrity without queues or premature services; throughput and HA are explicitly deferred.                                                                              |
| D-022 | Store the legacy Acme snapshot only in an immutable evaluation fixture catalog labeled non-authoritative and non-replayable.                                                                         | Accepted   | Authoritative durable cases enter only through runtime commands whose complete journal can be replayed.                                                                                                                      |
| D-023 | Bind the PR4 appliance to loopback, local PostgreSQL targets, simulation mode, and external writes disabled; make `fr up` select a verified repository Compose surface explicitly.                   | Accepted   | The unauthenticated evaluation API cannot be presented as a safe LAN or production service, and ambient Compose configuration cannot silently expand its scope.                                                              |
| D-024 | Reject JavaScript strings that PostgreSQL JSONB cannot preserve, including the null character and unpaired Unicode surrogates, before canonical hashing.                                             | Accepted   | Pure-engine identities and accepted commands cannot diverge from the canonical persistence representation.                                                                                                                   |
| D-025 | Serve the PR5 guided workbench and its schema-bound walkthrough from the existing loopback appliance as replaceable, non-authoritative presentation adapters.                                        | Accepted   | The first-run experience can expose the complete case story without granting authority, mutating canonical cases, making external writes, or presenting simulated observations as production receipts.                       |
| D-026 | Publish the inspectable Core, ECC evaluation pack, loopback appliance, and Guided Workbench under Apache License 2.0 while retaining Field Runtime trademarks and keeping packages registry-private. | Accepted   | Organizations receive a patent-granting, no-lock-in source license without implying production readiness, official status for forks, accidental package publication, or inclusion of separately offered enterprise services. |
