# Architecture Decisions

| ID    | Decision                                                                                                                                                                           | Status   | Consequence                                                                                                                                 |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | Position Field Runtime Core as an Enterprise Case Runtime, not a generic agent or workflow builder.                                                                                | Accepted | Product evaluation is case-first, not chat-first.                                                                                           |
| D-002 | Use a TypeScript pnpm monorepo and one modular deployable.                                                                                                                         | Accepted | Package boundaries are explicit without premature distributed systems.                                                                      |
| D-003 | Use PostgreSQL as the canonical persistence target.                                                                                                                                | Accepted | SQLite may not replace it silently; local convenience requires a future conformance decision.                                               |
| D-004 | Keep authority, scope, identity, state transitions, idempotency, and closure outside models.                                                                                       | Accepted | Agent and model outputs are proposals only.                                                                                                 |
| D-005 | Ship v0 as a synthetic, credential-free, no-external-write evaluation appliance.                                                                                                   | Accepted | Installation may be easy; production authority requires a separate graduation process.                                                      |
| D-006 | Put models, agent harnesses, memory systems, work surfaces, and connectors behind bounded adapters outside the trusted core.                                                       | Accepted | Providers are replaceable and cannot own canonical case state.                                                                              |
| D-007 | Make Escalation and Commitment Control the only initial workflow pack.                                                                                                             | Accepted | Product proof stays workflow-specific.                                                                                                      |
| D-008 | Defer public licensing until the distribution and commercial open-core boundary is approved.                                                                                       | Accepted | Absence of a license is intentional for the private scaffold.                                                                               |
| D-009 | Treat workflow YAML, authority YAML, canonical JSON Schema, and cross-record invariants as the v0 contract; keep generated PostgreSQL SQL as reference until parity is reconciled. | Accepted | Contract drift is explicit and cannot silently redefine runtime behavior.                                                                   |
| D-010 | Import ECC v0.1.0 as immutable shadow/evaluation-only and deny activation until graph, authority, fixture, and persistence parity blockers are repaired in a new version.          | Accepted | The baseline remains useful without overstating executable safety.                                                                          |
| D-011 | Keep normalized inbound `WorkEvent` records distinct from authoritative `CaseJournalEntry` history.                                                                                | Accepted | Source evidence retains its provider-neutral shape while aggregate replay gains sequence, attribution, causation, and hash-chain semantics. |
| D-012 | In PR2, attach a WorkEvent only to an explicitly identified case; defer automatic ECC candidate selection until its merge basis and ambiguity policy are executable.               | Accepted | The runtime cannot guess a case from insertion order or incomplete business discriminators.                                                 |
| D-013 | Deny every transition to `resolved` until the complete closure-proof engine can validate action/no-action, independent verification, commitments, accepted outcome, and audit.     | Accepted | PR2 demonstrates the lifecycle without making an unproved resolution authoritative.                                                         |
| D-014 | Journal an attributable transition rejection and advance aggregate version while leaving business state unchanged; malformed commands, conflicts, and duplicates do not append.    | Accepted | Investigations retain the attempted operation without confusing it with an accepted state change.                                           |
| D-015 | Treat PR2 as an in-memory reference engine; require PR4 to atomically persist journal, projection, idempotency, and source-event identity.                                         | Accepted | Deep freezing and hash validation do not imply process-safe concurrency or durable immutability.                                            |
| D-016 | Return an already-processed conflict when an exact source event is replayed under a fresh idempotency key; only the original same-key command is an exact duplicate.               | Accepted | PR2 avoids an unjournaled alias ledger while guaranteeing that the source event has no duplicate case effect.                               |
| D-017 | Fail closed on every claimed `executed` action until PR6 defines and recomputes a versioned authorization-envelope hash.                                                           | Accepted | Caller-declared hashes, approvals, and receipts cannot be mistaken for execution proof.                                                     |
